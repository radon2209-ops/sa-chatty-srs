# Спецификация требований к ПО — Chatty 2.0

Учебный проект в рамках курса «Системный анализ» (Яндекс Практикум, 2026).

## Контекст

Chatty — веб-приложение для изучения английского языка. В версии 2.0 добавляется словарь и карточки для изучения слов. Задача проекта — подготовить полную спецификацию требований (SRS) по методологии Karl Wiegers для команды разработки и тестирования.

## Что сделано

| Раздел | Содержание |
|--------|-----------|
| **Общее описание** | Контекстная диаграмма, классы пользователей (Ученик, Преподаватель), операционная среда, ограничения проектирования, предположения и зависимости |
| **Функции системы** | 6 функциональных блоков: словарь, карточки, статистика изучения, озвучка, видео в контексте, персональный словарь |
| **Use Cases** | Диаграмма и 8 детализированных сценариев с базовым потоком, расширениями, предусловиями и гарантиями успеха |
| **Функциональные требования** | Формализованные требования с уникальными кодами (ВИ-1 … ВИ-N) |
| **Нефункциональные требования** | Юзабилити, производительность (2000 пользователей, 500 в пик), безопасность, доступность (99% uptime) |
| **Приложения** | Глоссарий терминов, бизнес-правила (БП-1 … БП-3) |

## Методология и инструменты

- **Стандарт документации:** IEEE 830 / Karl Wiegers «Разработка требований к ПО»
- **Нотация диаграмм:** UML Use Case
- **Инструменты:** Draw.io, Microsoft Word

## Чему научился

- Формализовывать функциональные требования с уникальной трассируемостью (коды ВИ-N, УИ-N, Про-N)
- Описывать Use Cases с базовым сценарием, расширениями и негативными кейсами
- Разделять функциональные и нефункциональные требования, задавать измеримые метрики для последних
- Документировать бизнес-правила и связывать их с функциональными требованиями
